│ ▸ 在线模式   关  [ ●] │ ← 开关，圆点在右 = 开
│   深色模式   开  [● ] │ ← 开关，圆点在左 = 关
│   开机动画   开  [● ] │

### 1.2.1 开关（toggle）的画法

只有**布尔型**选项用开关，其余用文字/数字：

- 开关尺寸：约 36×20px，圆点直径 14px
- **关**：轨道灰 `#3a3a3a`，圆点在左
- **开**：轨道草绿 `#5da13f`，圆点在右
- 开关和状态文字（开/关）一起显示，避免只靠颜色判断

| 类型 | 展示方式 |
|---|---|
| 在线模式 / 深色模式 / 开机动画 | 行内开关 + 开/关文字 |
| 屏幕亮度 | 纯数字（0–100，步长 10） |
| 息屏时间 | 文字（15秒 / 30秒 / 1分钟 / 5分钟） |
| IP / SD 卡 / 固件 | 只读文字（次要色） |

### 1.2.2 菜单项一览

| 菜单项 | 类型 | 单击 `#` 的行为 |
|---|---|---|
| 在线模式 | 开关 | 关 ↔ 开（同时控制热点/网页/联网） |
| 深色模式 | 开关 | 深色 ↔ 浅色 |
| 开机动画 | 开关 | 关 ↔ 开（关掉则上电直接进播放界面） |
| 屏幕亮度 | 数字 0–100 | 每次 +10，到 100 回 0 |
| 息屏时间 | 4 档文字 | 15秒 → 30秒 → 1分钟 → 5分钟 → 循环 |
| IP 地址 | **只读** | 无反应 |
| SD 卡状态 | **只读** | 无反应（未检测到 / 已就绪 + 容量） |
| 固件 | **只读** | 无反应（只显示版本号，当前测试版 `11.4.1`） |

> IP 和 SD 卡状态在**进入菜单时读取一次**即可，不要实时刷新（避免每帧读网络/文件系统）。

### 1.2.3 息屏（保护液晶 + 省电）

| 档位 | 时间 |
|---|---|
| 1 | 15 秒 |
| 2 | 30 秒（默认） |
| 3 | 1 分钟 |
| 4 | 5 分钟 |

**⚠️ 息屏不能只关背光。**

便宜的 TFT 液晶长时间显示同一帧会产生**图像残留（image persistence）**：
关掉背光后面板仍在持续刷新，液晶分子一直处于局部偏置状态，
久了就会留下淡淡残影，需要很长时间才能恢复（不会烧屏，但很难受）。

正确流程（`tft_sleep()`）：

1. **整屏填充纯黑** —— 让所有像素回到同一状态，消除局部偏置；
2. **关背光** —— 用户看不到黑屏闪一下；
3. **面板休眠** —— `esp_lcd_panel_disp_sleep(panel, true)`，
   停止驱动液晶，这才是真正保护面板的一步。

唤醒（`tft_wake()`）：

1. `esp_lcd_panel_disp_sleep(panel, false)`；
2. **等 120ms**（ST7789 从 sleep out 恢复需要时间，早了会花屏）；
3. 开背光；
4. **重绘当前界面**（息屏时画面已清黑）。

- **息屏后按任意键，第一下只唤醒，不执行该键功能**（防误触）
- 唤醒后从按下算起，重新计时

> **不做全屏反色**：用户已确认不需要。
> 息屏功能的首要目的就是防图像残留（其次才是省电），
> 反色会额外占用 CPU 和带宽，收益不明显，不再考虑。

## 2. 按键时序（关键，容易写错）

### 2.1 各键功能表

| 键 | 播放界面 | 菜单 | 选歌 |
|---|---|---|---|
| `^` (K2) | 单击=上一首，长按=音量+ | 上一个选项 | 上移一项（长按连滚） |
| `v` (K1) | 单击=下一首，长按=音量− | 下一个选项 | 下移一项（长按连滚） |
| `*` (K4) | 单击=播放/暂停，长按=切模式，双击=选歌 | （同播放界面） | 单击=选中播放，双击=忽略 |
| `#` (K3) | 双击=进菜单（单击无功能） | 单击=调整，双击=退出 | 双击=退出 |

### 2.2 参数

| 参数 | 值 | 说明 |
|---|---|---|
| 消抖 | 20ms | 连续两次采样一致才认 |
| 长按阈值 | 600ms | 超过算长按，松手不再触发单击 |
| 长按重复 | 120ms/次 | 音量、选歌滚动 |
| 双击窗口 | 300ms | 两次按下间隔小于此值算双击 |

### 2.3 重要实现约定

**带双击功能的键，单击必须延迟执行。**

原因：双击 = 单击 + 单击。如果单击立即执行：
- `*` 双击进选歌时，音乐会被「暂停 → 播放」闪一下；
- 菜单里 `#` 双击退出时，选项会被切换两次（toggle 会抵消，但屏幕会闪）。

所以：`*` 和 `#` 的单击要等 300ms 确认不是双击，再执行。

**代价**：播放/暂停慢 300ms。已确认可接受。

**副产物（好事）**：菜单里 `#` 双击时，两次 toggle 正好抵消，设置值不会乱。但这只在「开/关型」选项上成立，所以菜单项一律做成 toggle，不要放「+1」这种单向操作。

## 4. 设置持久化：用 NVS，不用文件

**不要写配置文件**。用 ESP-IDF 的 NVS（键值存储）：

```c
nvs_set_u8(h, "dark", 1);       // 深色模式
nvs_set_u8(h, "online", 0);     // 在线模式
nvs_set_u8(h, "mode", 0);       // 播放模式 0=顺序 1=单曲 2=随机
nvs_set_u8(h, "vol", 60);       // 音量
nvs_set_u8(h, "bright", 70);    // 屏幕亮度
nvs_set_u8(h, "bootanim", 1);   // 开机动画 0=关 1=开
nvs_set_u8(h, "screenoff", 2);  // 息屏 0=15s 1=30s 2=1min 3=5min
nvs_commit(h);
```

**为什么不用文件**：文件会不断追加/新建，设置多了会吃满 Flash。NVS 是分区表里固定 24KB 的一小块，有磨损均衡，写几万次都没事，而且只占用这一块，不会长大。

**写入时机**：只在用户改设置时写一次，不要每帧写（Flash 写入会阻塞几十 ms）。

**写失败怎么办**：不能因为一次存储失败把设备搞崩。写入返回值非 ESP_OK 时，
保留内存里的值、在屏幕上提示一下即可，不要 abort。

| NVS Key | 类型 | 范围 | 默认 |
|---|---|---|---|
| `dark` | u8 | 0=浅色 1=深色 | 0 |
| `online` | u8 | 0=关 1=开 | **0（默认关）** |
| `mode` | u8 | 0=顺序 1=单曲 2=随机 | 0 |
| `vol` | u8 | 0–100 | 60 |
| `bright` | u8 | 0–100 | 70 |
| `bootanim` | u8 | 0=关 1=开 | 1 |
| `screenoff` | u8 | 0=15秒 1=30秒 2=1分钟 3=5分钟 | 1 |

> `mode` 和 `vol` 虽然不在菜单里，但同样要持久化——用户调过的值关机后要保持。

## 5. 在线模式：后台联网，不能卡 UI

### 5.1 架构

```
┌─────────────┐  状态/结果   ┌──────────────┐
│  UI 任务     │◄───────────│  网络任务     │
│  30~60fps   │   队列       │  (联网/搜索)  │
└─────────────┘             └──────────────┘
```

- UI 任务**永远不调用**阻塞式网络 API
- 网络任务负责：连 WiFi、搜索、下载
- 中间通过队列传结果，UI 只读状态

### 5.2 在线模式开关的行为（三合一）

用户要求：在线模式**同时控制热点、网页、联网**，三者同开同关。

| 状态 | AP 热点 | HTTP 网页 | 连路由器 / 搜歌 |
|---|---|---|---|
| **关闭（默认）** | 关 | 关 | 不连，不可用 |
| 打开 | 开 | 开 | 读 NVS 自动连，可用 |

**代价**：关闭后设备完全不在网络上，只能通过**屏幕菜单**重新打开。

> ⚠️ 风险：如果屏幕或按键坏了，设备将无法再连入。
>
> **保险方案（已定，选 A）**：**长按 `#` + `*` 5 秒，强制开热点**，不受在线模式限制。
>
> - 实现时机：跟「在线模式开关」一起做。现在热点还是常开的，没有「关闭」逻辑，
>   所以这个保险暂时没地方触发。
> - 行为：两键同时按住满 5 秒 → 立即启动 AP + HTTP 服务，屏幕给个提示（如「热点已开」）；
>   松手后热点保持开启，直到用户手动关掉在线模式或重启。

### 5.3 状态显示

在线模式打开后，状态栏的 WiFi 图标显示四种状态，但**都不要阻塞 UI**：

| 状态 | 图标表现 |
|---|---|
| 未连接 | 灰色，无信号格 |
| 连接中 | 闪烁 |
| 已连接 | 亮色 + 信号格 |
| 失败 | 灰色 + 小叉，后台继续重试 |

## 7. 性能预算

| 项目 | 数值 | 说明 |
|---|---|---|
| SPI 时钟 | 40MHz | 240×240×16bit 全屏 ≈ 23ms |
| 目标帧率 | 30fps | 全屏刷新达不到，靠局部刷新 |
| 唱片旋转 | 预渲染 16 帧 | 每帧约 20KB（100×100），共 320KB，放 PSRAM |
| 开机动画 | 约 1.5s | Logo 放大 + 淡入，只刷变化区域 |
| 歌名滚动 | 局部刷新 | 只刷歌名那一行 |

**关键**：能局部刷新就局部刷新，整屏重绘一帧 23ms，30fps 只有 33ms 预算，几乎不剩。

## 8. 已取消的功能

**下载到 SD 卡 —— 已删除**（2026-10-20）。

- 前端：歌曲条目上的「↓」按钮、`download()` 函数、相关 CSS 全部移除
- 后端：`/download` 和 `/download/status` 两个路由及处理函数移除

原因：iTunes 只给 30 秒的 **AAC（.m4a）** 片段，helix 只能解 MP3，下载下来本地也播不了；而且只有 30 秒，没有下载价值。在线搜歌只做「试听」，想听完整的把歌放进 SD 卡。

## 9. 依赖与顺序

1. **SD 卡**（未到货）：选歌界面需要它列文件。先做 SD，再做选歌。
2. **I2S/PCM5102A**（未到货）：播放功能需要它。UI 可以先跑假数据。
3. **屏**（未到货）：当前已有自检代码（四色块 + 按键换色）。

建议顺序：屏点亮 → 按键 → 菜单（不需要音频）→ SD 卡 → 选歌 → I2S 播放。
